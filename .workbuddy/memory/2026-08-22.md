# 2026-08-22 设置页 ModelPicker 崩溃 + 厂商模型问题分析

## 故障根因
- `App.ModelPicker` 为 undefined → `renderer.js:581 App.ModelPicker.init()` 抛 TypeError。
- 真正原因:`desktop/src/ui/js/model_picker.js` 含 TypeScript 类型注解(`let _selectedModels: Record<...>` / `const counts: Record<...>`),纯 .js 文件解析失败,整个模块不加载。
- 顺带发现 `chat.js` 也有同类问题(`const body: any = {...}` 两处),会导致聊天模块整体崩溃("部分组件不显示")。

## 修复(已写入源码)
- `model_picker.js`:删除 2 处 TS 类型注解。
- `chat.js`:删除 2 处 `const body: any` 注解。
- 全量扫描 `desktop/src` 所有 .js,确认无残留 TS 语法,`node --check` 全部通过。
- 设置项"厂商模型添加/选择"根因:`provider_registry` 同时存 `model`(默认)与 `models`(数组),但选择器/管理面板/厂商列表只读 `models`。当 `models:[]` 而 `model` 有值时,显示"0 个模型"且选择器无模型可选。
  - `app/core/provider_registry.py` `list_models`:`models` 为空但 `model` 有值时兜底返回单元素列表。
  - `app/api/chat.py` `list_providers`:`model_count` 改用 `list_models` 计数。
  - `app/api/tools.py` `GET /v1/providers/custom`:`models` 改用 `list_models`(含兜底)。
  - `desktop/src/ui/js/settings.js` `_openProvForm`:`p.models` 为空但存在默认 model 时,用默认 model 占位,避免编辑时丢失。

## 部署现状(重要)
- 运行中的后端 = `desktop/backend/dist/agent-backend/agent-backend.exe`(旧构建,数据读 `dist/.../data/providers.json`)。
- 前端 Electron 部署为冻结 `desktop/out/asar` 包,加载的是打包时快照的 `src/ui`,**不会**自动反映 `src/ui` 源码改动。
- 因此源码修复需重新构建才生效:① 后端 exe 重建(此前有 pydantic `_pydantic_core` DLL 缺失问题,`hooks/hook-pydantic_core.py` 已存在但未彻底解决);② Electron `npm run dist` 重新打包 `src/**/*` + 新 exe。
- `npm start`(electron .)dev 模式直接加载 `src/ui`,刷新即生效;打包版需重建。

## 验证

- Python `list_models` 逻辑测试:空 models 厂商正确返回 `[{id: agnes-2.0-flash, default:true}]`,计数=1;正常厂商不变。
