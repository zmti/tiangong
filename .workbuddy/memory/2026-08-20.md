## 二次修复：空 done 事件被误判为"响应中断"
- 用户截图 DevTools 显示 `res {done:false, value:Uint8Array(226)}`，随后界面报"响应中断"
- 复现：对 `{"message":"11","session_id":"test-full","mode":"ensemble"}`，后端只返回 226 字节 `data:{"type":"done",...}\n\n`，无 token
- 根因：`reader.read()` 二次调用抛错后进入 catch，外层 `if (!done && !receivedTokens)` 未排除"已收到事件"的情况，导致空 done 被误判为"响应中断"
- 修复 `chat.js`：
  - 新增 `receivedAnyEvent` 标记，成功解析任意 SSE 事件即置 true
  - 显式声明 `let value = null`，避免隐式全局变量
  - `reader.read()` catch 中若已收到事件则不再标记 `isError`
  - 最终判断改为 `if (!done && !receivedTokens && !receivedAnyEvent && !isError)`
- 启动障碍：当前 shell 环境变量 `ELECTRON_RUN_AS_NODE=1` 导致 `npm start` 把 electron 当 node 跑、`app` 未定义；解决：`unset ELECTRON_RUN_AS_NODE` 并指定独立 `--user-data-dir` 后成功启动
- 最终通过命令 `unset ELECTRON_RUN_AS_NODE && ./node_modules/electron/dist/electron.exe --no-sandbox --user-data-dir="E:/dev/agent-service/electron_userdata_dev" .` 启动成功，后端 8517 正常服务
- **用户实测确认：对话功能已正常**（实时逐字显示、不超时、不报中断）。说明此前 chat.js 的渲染整段重渲染 + 建连30s超时 + 空闲间隙续期 + 空done兜底 + value/receivedAnyEvent 修复组合生效
- 遗留：当前 WorkBuddy shell 常驻 `ELECTRON_RUN_AS_NODE=1`，在该终端 `npm start` 需先 `unset`，否则 electron 退化为纯 node 报 app undefined；待用户决定是否固化到 package.json/main.js。后端 ensemble 空输入只回空 done 的 bug 前端已兜底，根因未改。
